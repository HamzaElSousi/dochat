## Spacing Scale

Declared values. Pico.css uses `--pico-spacing: 1rem` (16px) as the base unit. The custom CSS block for drop zone and spinner overrides follows an 8-point grid mapped to Pico's `rem`-based scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Icon gaps, close-button padding inside error alert |
| sm | 8px (0.5rem) | Inline element gaps, status badge padding, table cell compact padding |
| md | 16px (1rem) | Default element spacing — Pico `--pico-spacing` base |
| lg | 24px (1.5rem) | Drop zone internal padding (top/bottom), section gap between upload form and document table |
| xl | 32px (2rem) | Nav bar height, major section vertical margin |
| 2xl | 48px (3rem) | Drop zone min-height |
| 3xl | 64px (4rem) | Page-level container top/bottom padding |

Exceptions:
- Drop zone `min-height` is 96px (6rem) — not on the 8-point scale, driven by usability (enough click/drop surface area)
- Nav bar items use 12px (0.75rem) horizontal padding — Pico's `<nav>` default, not overridden

## Typography

Pico.css v2 sets `--pico-font-size: 100%` on `<html>` (16px browser default). Heading scale follows HTML semantic heading sizes. The admin panel uses 4 type roles:

| Role | Size | Weight | Line Height | Element |
|------|------|--------|-------------|---------|
| Body | 16px (1rem) | 400 (regular) | 1.5 | `<p>`, `<td>`, `<label>`, `<small>` |
| Label / UI | 14px (0.875rem) | 400 (regular) | 1.4 | Status badge text, table header `<th>`, nav link text |
| Heading | 20px (1.25rem) | 700 (bold) | 1.2 | `<h2>` — page section headings ("Documents", "Upload a Document") |
| Display | 28px (1.75rem) | 700 (bold) | 1.2 | `<h1>` — page title in nav bar ("DocChat Admin") |

**Font weight contract:** Exactly 2 weights in use — 400 (body/label) and 700 (headings). No 500, 600, or 800.

**Source:** Pico.css v2 defaults (`--pico-font-weight: 400`, `--pico-line-height: 1.5`). Heading sizes follow browser UA sheet scaled by Pico. No overrides needed.

## Color

Pico.css v2 uses a light theme by default. The admin panel uses light theme (no dark mode toggle for MVP). Colors reference Pico's CSS custom properties — do not hardcode hex values in templates.

| Role | CSS Variable | Light Value | Usage |
|------|-------------|-------------|-------|
| Dominant (60%) | `--pico-background-color` | `#ffffff` | Page background, table rows |
| Secondary (30%) | `--pico-card-background-color` | `#f9f9fb` | Nav bar background, upload form card background |
| Accent (10%) | `--pico-primary` | `#0172ad` | Upload button, URL Submit button, nav active indicator |
| Destructive | `--pico-del-color` / custom `#c0392b` | `#c0392b` | Delete (✕) button only |
| Text | `--pico-color` | `#373c44` | All body text, table data |
| Muted | `--pico-muted-color` | `#646b79` | Status badge text, empty state body copy, timestamp |
| Error surface | custom `#fdecea` | `#fdecea` | Inline error message box background |
| Error border | custom `#c0392b` | `#c0392b` | Inline error message box left border (4px solid) |

**Accent reserved for:** Upload File button, Submit URL button, nav link active state. NOT used for status badges, table rows, or read-only elements.

**Destructive reserved for:** ✕ delete button only. Rendered as muted gray by default, turns `#c0392b` on `:hover` to signal danger before click.

**Source:** Pico.css v2 defaults from `--pico-*` variables (CONTEXT.md D-06). Error surface colors are custom — defined in a `<style>` block in `base.html`.

## Component Contracts

### 1. Base Layout (`templates/admin/base.html`)

```
<html lang="en">
  <head>

  </head>
  <body>
    <header>
      <nav>
        <ul><li><strong>DocChat Admin</strong></li></ul>
        <ul>
          <li><a href="/dochat/admin/docs">Documents</a></li>
          <li><a href="/dochat/admin/leads">Leads</a></li>
        </ul>
      </nav>
    </header>
    <main class="container">
      {% block content %}{% endblock %}
    </main>
  </body>
</html>
```

Nav bar: Pico `<header><nav>` pattern. Active page link gets `aria-current="page"` attribute.

### 2. Drop Zone (`templates/admin/docs.html` — upload section)

HTML structure:
```html
<div id="drop-zone" role="button" tabindex="0" aria-label="Drop files here or click to browse">
  <p id="drop-zone-label">Drag &amp; drop a PDF, DOCX, TXT, or MD file here</p>
  <p><small>or</small></p>
  <input type="file" id="file-input" accept=".pdf,.docx,.txt,.md" hidden>
  <button id="browse-btn" type="button">Choose File</button>
  <div id="spinner" hidden aria-live="polite">
    <span class="spinner-icon" aria-hidden="true"></span>
    <span>Uploading...</span>
  </div>
</div>
```

Drop zone state contracts:

| State | Visual | CSS |
|-------|--------|-----|
| Default / ready | Light gray dashed border 2px, background `#f9f9fb`, border-radius 8px | `border: 2px dashed #ccc; background: #f9f9fb;` |
| Dragover (file hovering) | Border becomes 2px solid `--pico-primary` (`#0172ad`), background `#eaf4fc` | Apply class `dragover` on `dragover` event, remove on `dragleave`/`drop` |
| Uploading | Spinner visible, label text replaced with "Uploading...", browse button disabled, input disabled, drop zone pointer-events none | Add class `uploading`; show `#spinner`; disable `#browse-btn` and `#file-input` |
| Success | Drop zone returns to Default state; new row appended to table below | Remove `uploading` class; hide spinner; restore button |
| Error | Drop zone returns to Default state; inline error box appears below drop zone | Remove `uploading` class; show `#upload-error` div |

Spinner CSS (in `<style>` block in base.html):
```css
.spinner-icon {
  display: inline-block;
  width: 16px;
  height: 16px;
  border: 2px solid #ccc;
  border-top-color: var(--pico-primary);
  border-radius: 50%;
  animation: spin 0.7s linear infinite;
}
@keyframes spin { to { transform: rotate(360deg); } }
```

Drop zone custom CSS:
```css
#drop-zone {
  border: 2px dashed #ccc;
  border-radius: 8px;
  padding: 1.5rem;
  text-align: center;
  min-height: 96px;
  cursor: pointer;
  transition: border-color 0.15s, background-color 0.15s;
}
#drop-zone.dragover {
  border-color: var(--pico-primary);
  background-color: #eaf4fc;
}
#drop-zone.uploading {
  pointer-events: none;
  opacity: 0.7;
}
```

### 3. URL Submission Form

HTML structure:
```html
<form id="url-form" aria-label="Submit a URL for crawling">
  <label for="url-input">Submit a URL</label>
  <div role="group">
    <input type="url" id="url-input" name="url"
           placeholder="https://example.com/page"
           required aria-describedby="url-hint">
    <button type="submit" id="url-submit-btn">Crawl &amp; Index</button>
  </div>
  <small id="url-hint">The page will be crawled and its text content indexed.</small>
</form>
```

States:
- Default: input enabled, button enabled, hint visible
- Submitting: button text becomes "Crawling...", button disabled, input disabled
- Success: form resets to default; new row appended to document table
- Error: form resets to default; inline error box shown

### 5. Document Table (`templates/admin/docs.html` — table section)

```html
<table role="grid" aria-label="Indexed documents">
  <thead>
    <tr>
      <th scope="col">Filename</th>
      <th scope="col">Type</th>
      <th scope="col">Upload Date</th>
      <th scope="col">Status</th>
      <th scope="col">Chunks</th>
      <th scope="col">Actions</th>
    </tr>
  </thead>
  <tbody id="doc-table-body">
    <!-- rows appended by JS on success, or server-rendered on page load -->
  </tbody>
</table>
```

Column widths (approximate, not fixed — Pico auto-layout):
- Filename: ~35% (longest content)
- Type: ~8% (PDF / DOCX / TXT / MD / URL)
- Upload Date: ~18% (ISO datetime, formatted as "MMM D, YYYY HH:MM")
- Status: ~12% (badge)
- Chunks: ~8% (integer, right-aligned)
- Actions: ~8% (single ✕ button, centered)

Document row HTML template (used by JS `appendDocRow(doc)` and server-side render):
```html
<tr id="doc-row-{doc_id}" data-doc-id="{doc_id}">
  <td>{filename}</td>
  <td>{type}</td>
  <td><time datetime="{iso_datetime}">{display_datetime}</time></td>
  <td><span class="status-badge status-{status}">{status}</span></td>
  <td style="text-align:right">{chunk_count}</td>
  <td style="text-align:center">
    <button class="delete-btn" data-doc-id="{doc_id}" data-filename="{filename}"
            aria-label="Delete {filename}" title="Delete document">&#x2715;</button>
  </td>
</tr>
```

## Interaction Contracts

### Drop Zone — Drag and Drop

Events to handle (vanilla JS, HTML5 native):

| Event | Target | Action |
|-------|--------|--------|
| `dragover` | `#drop-zone` | `preventDefault()`; add class `dragover` |
| `dragleave` | `#drop-zone` | Remove class `dragover` |
| `drop` | `#drop-zone` | `preventDefault()`; remove class `dragover`; extract `event.dataTransfer.files[0]`; call `uploadFile(file)` |
| `click` | `#browse-btn` | `document.getElementById('file-input').click()` |
| `change` | `#file-input` | Extract `event.target.files[0]`; call `uploadFile(file)` |

### Upload Flow (XHR)

```
uploadFile(file)
  → add class 'uploading' to #drop-zone
  → show #spinner; hide #drop-zone-label and #browse-btn
  → disable #file-input and #browse-btn
  → POST FormData to /dochat/admin/ingest/upload
  → on success (JSON: {doc_id, filename, type, upload_date, status, chunk_count}):
      appendDocRow(response)  → prepend <tr> to #doc-table-body
      resetDropZone()
  → on error (JSON: {error: "..."} or network fail):
      resetDropZone()
      showError(message)
```

### URL Submit Flow (XHR)

```
#url-form submit handler
  → preventDefault()
  → disable #url-input and #url-submit-btn; set button text to "Crawling..."
  → POST JSON {url: value} to /dochat/admin/ingest/url
  → on success:
      appendDocRow(response)
      resetUrlForm()
  → on error:
      resetUrlForm()
      showError(message)
```

### Delete Flow

```
click on .delete-btn
  → read data-filename, data-doc-id
  → confirm("Delete [filename]? This removes all indexed chunks.")
  → if confirmed:
      DELETE /dochat/admin/docs/{doc_id}
      on success (200): remove tr#doc-row-{doc_id} from DOM
      on error: showError("Could not delete document. Please try again.")
```

### Error Dismiss

```
click on #dismiss-error
  → set #upload-error to hidden
  → clear #upload-error-text
```

## Static File Contract (`static/admin.js`)

Target: approximately 80 lines. No external JS libraries. Functions:

| Function | Purpose |
|----------|---------|
| `uploadFile(file)` | XHR POST to `/dochat/admin/ingest/upload` with FormData |
| `submitUrl(url)` | XHR POST to `/dochat/admin/ingest/url` with JSON body |
| `appendDocRow(doc)` | Builds and prepends `<tr>` to `#doc-table-body` using doc JSON |
| `showError(message)` | Populates `#upload-error-text` and removes `hidden` from `#upload-error` |
| `resetDropZone()` | Removes `uploading` class, hides spinner, re-enables input and button |
| `resetUrlForm()` | Re-enables URL input, resets button text to "Crawl & Index", re-enables button |
| `deleteDoc(docId, filename)` | Shows `confirm()` dialog; on confirm, sends DELETE, removes row on success |
| Event wiring (top-level) | `DOMContentLoaded` listener attaches all event handlers |

## Accessibility Contract

- All interactive elements have `aria-label` or visible label
- Drop zone has `role="button"` and `tabindex="0"` (keyboard accessible)
- Error alerts use `role="alert"` and `aria-live="assertive"`
- Upload spinner uses `aria-live="polite"` so screen readers announce "Uploading..."
- Table uses `role="grid"` and `scope="col"` on all `<th>` elements
- Nav active link has `aria-current="page"`
- Delete button aria-label includes the filename: "Delete report.pdf"
- `<time>` elements used for all dates with machine-readable `datetime` attribute

## Responsive Contract

Admin panel is desktop-first. Pico.css `<main class="container">` provides max-width centering with fluid margins. No mobile breakpoint overrides needed in MVP.

Minimum usable width: 768px. Below this width, table columns may overflow — acceptable for MVP (admin is single user on desktop browser).
