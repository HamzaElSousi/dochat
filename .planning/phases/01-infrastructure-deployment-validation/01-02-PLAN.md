**If HTTP 500 occurs — diagnostic sequence:**
1. Check Passenger error log (cPanel → Error Logs or `tail ~/logs/error_log`)
2. Common cause: `KeyError: 'SECRET_KEY'` → `.env` was not created or load_dotenv path is wrong
3. Common cause: `No module named 'flask'` → virtualenv not activated or pip install not run
4. Common cause: `No such file 'passenger_wsgi.py'` → Application root mismatch in cPanel Python Selector (Pitfall 3)
5. After fixing, always run `touch tmp/restart.txt && touch passenger_wsgi.py`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SiteGround server → .env file | Secrets in .env must not be readable by other hosting accounts |
| git push → GitHub | .env must never appear in any commit |
| curl → /health | Public endpoint; must not leak server internals |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | .env on SiteGround | accept | SiteGround shared hosting user isolation is out of our control; .env lives at ~/dochat/.env (not public_html/); SiteGround is trusted provider |
| T-02-02 | Information Disclosure | git history | mitigate | `git status` check before commit confirms .env not staged; .gitignore enforces exclusion |
| T-02-03 | Information Disclosure | /health storage_path field | accept | Path reveals home directory structure; acceptable — /health is intentionally public (D-03) and path contains no secrets |
| T-02-04 | Denial of Service | Passenger single-worker | accept | PassengerMaxPoolSize 1 is the intended config for shared hosting; DDoS mitigation is SiteGround's responsibility |
</threat_model>
